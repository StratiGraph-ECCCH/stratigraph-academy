# The map of the tools

The tools of the ecosystem, one sentence each, so that the names in the rest of
this manual mean something. The ones in **bold** are explained in this manual;
the others have their own.

## The node and what it holds

**StratiGraph Server** — the node: it holds rooms, the people who may enter
them, the files a study brings with it, and the doors other tools knock on.

**The catalogue** — what a node publishes of itself to whoever is allowed to
look: studies, resources, and the words they use.

**The web interface of the graph** — where a published study can be questioned
with a query rather than only read page by page.

Behind these sit the services a node needs and rarely names: the graph store,
the database of documents and revisions, the object store for files, the
identity service, and the IIIF image service. The deployment page of the node
manual says which ones a node brings and which it asks of the house.

## On site

**StratiField** — the field assistant: it records stratigraphic units,
photographs and observations from a trench, and keeps working when the node is
unreachable.

**The voice and language models** (ARC) — what turns a sentence said with both
hands busy into text, on the device itself, with no network and no cloud
service behind it.

**stratigraph-templates** — the recording sheets and the controlled vocabularies
a node serves, so that two excavations that never met still use the same words.

## Reading, modelling, arguing

EMStudio — the sovereign Extended Matrix editor: where a graph is drawn, read
and argued, on the desktop and in a browser.

EM Tools — the Blender add-on: where the reconstruction is modelled and tied,
piece by piece, to the units it represents.

3D Survey Collection — the Blender pipeline that prepares what a survey
produced, so that it arrives in the graph as something a study can refer to.

The point cloud toolbox (FBK) — what turns a measured cloud into the proxies
that stand for a unit when the unit is a volume rather than a line on a plan.

Aïoli (CNRS) — annotation on the 3D surface itself: what you see on the stones,
written on the stones, and brought back as evidence into the study.

s3Dgraphy — the library underneath all of them: it holds the graph, the
ontology and the rules that say which link is allowed.

## Publishing, and the tools an excavation already has

Heriverse — where a reconstruction becomes something a visitor can walk
through.

Tropy (UniLu) — where the photographs of an archive become described,
searchable material that a study can cite.

pyArchInit (AdArte) — the QGIS environment many Italian excavations already
record in, and one of the ways a legacy archive enters the graph.

Beyond these, the ecosystem expects an excavation to keep its own habits:
other recording systems, photogrammetry suites, GIS, institutional archives.
They plug in where they are good, and the interpretation stays in the graph.
